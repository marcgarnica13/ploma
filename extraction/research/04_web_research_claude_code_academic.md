## Thread 2 — The "lisa" harness

**Identity**: `github.com/codyswann/lisa` returns 404. The project is **github.com/CodySwannGT/lisa**, published as npm **`@codyswann/lisa`** (v4.84.x, Oct 2026, MIT, default branch `main`; description "Claude Code governance framework – guardrails, guidance, and automated enforcement for AI‑assisted development"). Unrelated namesakes: blencorp/lisa (spec interview for Ralph loops), tarcisiopgs/lisa, tonycasey/lisa.

Sources: README (https://github.com/CodySwannGT/lisa), AGENTS.md, `.claude-plugin/marketplace.json`, `plugins/src/base/.claude-plugin/plugin.json`, `plugins/src/base/hooks/*.sh`, `plugins/src/base/skills/*/SKILL.md`, issue #4335 (https://github.com/CodySwannGT/lisa/issues/4335), skills index (https://skills.lc/CodySwannGT/lisa).

### What it is
"Turns a repository into **software factories** — agent‑operated production lines running Research → Plan → Implement → Verify." Four faces: factory operator, standards engine, OS for coding agents, configuration library. Supports Claude Code, Codex, Cursor, OpenCode, Antigravity, Copilot, Devin (Claude is the reference; parity rule: "document gaps rather than silently drop behavior").

### Core concepts (exact terms)
- **Lifecycle**: *Understand → Plan → Build → Prove → Learn* (commands `understand/plan/build/prove/learn`, mostly as sub‑flows of `/lisa:implement`).
- **Intake / intent**: an **intake agent adversarially evaluates inputs** before work starts ("Humans don't operate inside a factory. Handoffs happen at the gate"); intake first tries to resolve gaps itself, escalates only what it genuinely can't. `lisa-intake`, `lisa-intake-explain`, `lisa-design-intake` (resolves source of truth per axis "never by asking a human", then a script decides). The term "intent" appears as a rule file `rules/eager/intent-routing.md`.
- **"State of the art"**: *not* a lisa concept. The closest things are `lisa-research`, `lisa-codebase-research`, and the wiki ("`wiki/` is the durable source of truth"). If your reference model has a "SOTA" phase, it is your addition, not lisa's.
- **Self‑verification / evidence**: "prove it, don't assume it"; "work is not 'done' because an agent says so". `lisa-verification-lifecycle` is a **mandatory 9‑step sequence**: 1 Confirm quality gates (tests/lint are *prerequisites, not verification*) → 2 Classify empirical verification types → 3 Check tooling → 4 Fail fast/escalate → 5 Plan (tool, expected pass outcome, prerequisites; "a plan listing only `bun run test` is NOT a verification plan") → 6 Execute (each result labelled `verified empirically` or `artifact-only / verification deferred`; run a *known‑good control spec* before trusting an environment) → 7 **Codify** (every passing empirical check becomes a regression test; mandatory) → 8 Spec conformance → 9 Loop.
- **Phases / roles**: factories (Research, Plan, Implement, Verify) + three feeding loops (QA, Product Planning, Monitoring); 30 agents in `plugins/src/base/agents/` (`builder`, `verification-specialist`, `spec-conformance-specialist`, `learner`, `learning-judge`, `learnings-synthesizer`, `skill-evaluator`, `eval-specialist`, …).
- **State files**: `.lisa.config.json` (harness, scheduler, starter sync), `.lisaignore`, `.lisa/apply-receipt.json`, `.lisa/work-item-context.md` (git‑ignored, verbatim work‑item bundle), **`.lisa/verification-status.json`** (schema v2: `claims[] {claim_id, statement, boundary, required_evidence_kinds, status established|not-established, evidence_refs}` + `evidence[] {kind, locator, sha256, captured_at, artifact_head_sha}` + `not_established_reviewed`), **`.lisa/PROJECT_LEARNINGS.md`** (machine‑written learnings ledger), `wiki/` (`wiki/index.md`, `wiki/log.md`, `wiki/gaps.md`, `wiki/sources/`, `wiki/state/agent-ready/sources.json`), `.claude/rules/PROJECT_RULES.md` (**human‑authored only** — "the humans' decree surface. Automated flows never append to it").
- **Governed templates**: three ownership modes — *enforced* (overwritten on update), *created‑once* (project‑owned after seeding), *merged*; `.lisaignore` opts files out; `package.lisa.json` with `force/defaults/merge` sections compiles into a clean `package.json`.
- **Single source, many destinations**: agent content authored once under `plugins/src/base/` and compiled to `-cursor`, `-copilot`, `-devin`, `-agy` variants; a **drift guard** CI check fails if generated artifacts diverge from source; "edit at the source, never in generated output".
- **Learn phase**: `/lisa:debrief` mines tickets/PRs/review threads into a triage doc; `/lisa:debrief:apply` persists; `lisa-persist-learning`; a "gardener" (`/lisa:learnings:audit`) proposes promotions/demotions/retirements as human‑gated tickets; rule `learnings-ladder.md`. Aim: PROJECT_RULES.md "shrinks instead of growing" as prose is replaced by hooks/lints.

### Onboarding ("lisa‑onboard" equivalent)
There is no `onboard` command; the equivalents are:
- **`/lisa:agent-ready`** (`lisa-agent-ready` skill): "*Starting tomorrow, you — the agent — maintain this project without any human input. Today is your only chance to ask questions.*" Phase 0 preflight: ensure `wiki/`, inventory every source (repo + full git history, tracker, MCP servers, CI, deployed envs; "an inaccessible source is still an inventoried source"), write `wiki/state/agent-ready/sources.json` with per‑source `terminal_status: complete|partial|unavailable`; read‑only, redacted ingestion; write **`wiki/gaps.md`** with only questions a human must answer ("A gap is (a) not derivable from any reachable source and (b) dangerous to guess… Not a gap: anything you can derive by reading harder"); re‑runs are **absorption runs** that ingest answered gaps; converge until zero gaps.
- `lisa doctor` (readiness audit), `lisa apply .` (writes templates/hooks/plugins + receipt), `lisa-setup-*` skills (workstation, local‑env, github, jira, …), `lisa-wiki-onboard-me` (onboard a *human* via the wiki), `docs/agentic-readiness-questionnaire.md`.

### How verification loops are enforced (mechanisms, not prose)
1. **Layered gates**: session rules (context) → git hooks via `.husky` (hard stops on commit/push) → agent hooks (PreToolUse/PostToolUse/Stop).
2. **Stop‑hook completion gate** `hooks/enforce-verification-gate.sh`: armed on `UserPromptSubmit` (prompt starts `/lisa:implement`) or `PreToolUse` (Skill tool loads `lisa-implement`); `SubagentStart` marks teammates exempt; on **`Stop`** it blocks the lead "unless a FRESH terminal verdict (status pass|blocked, all criteria pass) exists" in `.lisa/verification-status.json`, "bounded by a per‑session block counter so a genuinely‑stuck flow ESCALATES instead of looping forever". Its header explicitly contrasts with Claude Code's native `/goal` evaluator: "deterministic and judges a structured artifact the verification‑specialist writes from REAL tool output, so it is … not foolable by a prose claim of success".
3. Other guard hooks: `block-no-verify.sh`, `block-instruction-file-edits.sh`, `block-managed-file-edits.sh`, `block-blind-automerge.sh`, `enforce-team-first.sh`, `secrets-preflight.sh`, `threshold-ratchet.mjs` (quality thresholds only move up), `stale-state-claims` rule, `failure-signature-index.sh`, `worktree-binding-guard`.
4. **Rules shipped by a plugin**: because Claude Code does not load plugin `rules/` or `CLAUDE.md`, lisa ships `rules/eager/*.md` (26 files: `verification.md`, `falsifiable-checks.md`, `measurement-integrity.md`, `report-actionability.md`, `settled-decisions.md`, `tool-access-gate.md`, …) and `rules/reference/*.md`, and **`hooks/inject-rules.sh` concatenates `rules/eager/*.md` into `hookSpecificOutput.additionalContext` on `SessionStart` and `SubagentStart`**; reference bodies load only when an eager breadcrumb points at them. Hooks are declared **inline in `plugin.json` `"hooks"`** (not a separate `hooks/hooks.json`), paths via `${CLAUDE_PLUGIN_ROOT}/hooks/…`.
5. Issue #4335 shows a real failure mode: retiring hook scripts during an upgrade broke live sessions (exit 127) — lesson: *never delete a hook target mid‑session; keep old commands valid until a reload boundary*.

### Layout & install
- Repo: `plugins/src/base/{.claude-plugin/plugin.json,.mcp.json,agents/,commands/,hooks/,rules/{eager,reference}/,skills/ (172 `lisa-*` skills)}`; root `.claude-plugin/marketplace.json` (name `lisa`, `pluginRoot ./plugins`, 50 plugins: `lisa`, `lisa-typescript`, `lisa-rails`, `lisa-wiki`, … + per‑agent variants); `wiki/`, `plans/`, `specs/`, `evidence/`, `transcripts/`, `state/`, `.agents/rules/`, `.claude/rules/`.
- Install (Claude Code): `/plugin marketplace add CodySwannGT/lisa` → `/plugin install lisa@lisa`. Per‑repo governance: `bun add --dev --trust @codyswann/lisa` → `lisa apply .` → `lisa doctor`; workstation: `npx -y @codyswann/lisa@latest workstation --install --provider=bitwarden`.
- Commands are thin: each `commands/*.md` just says "Use the /lisa-<x> skill to …" (commands = user entry points, skills = the procedure).

## Thread 3 — Claude Code plugin packaging (official docs, current)

Primary pages: manifest reference https://code.claude.com/docs/en/plugins-reference.md ; components https://code.claude.com/docs/en/plugins/components.md ; create https://code.claude.com/docs/en/plugins/create.md ; marketplaces https://code.claude.com/docs/en/plugin-marketplaces.md , https://code.claude.com/docs/en/plugins/marketplace-reference.md , https://code.claude.com/docs/en/plugins/host-marketplace.md ; evals https://code.claude.com/docs/en/plugin-evals.md ; CLI https://code.claude.com/docs/en/plugins/cli-reference.md ; skills https://code.claude.com/docs/en/skills.md ; hooks https://code.claude.com/docs/en/hooks.md ; CLAUDE.md/rules https://code.claude.com/docs/en/claude-md.md

**`plugin.json`** (at `.claude-plugin/plugin.json`; optional — without it the standard layout still loads). Only `name` required (kebab‑case; reserved: starts with `claude-`/`anthropic-`/`cc-plugin-`). Fields: `displayName`, `version` (pins users until changed; omit to track commits), `description`, `author{name,email,url}`, `homepage`, `repository`, `license`, `keywords`, `metadata` (free‑form), `defaultEnabled`, `dependencies` (`"name"`, `"name@marketplace"`, or object w/ version), `settings` (only `agent`, `subagentStatusLine` take effect), **`userConfig`** (typed prompts: `string|number|boolean|directory|file`, `options`, `sensitive`→keychain, `multiple`; referenced as `${user_config.KEY}` in skill/agent text and exported as `CLAUDE_PLUGIN_OPTION_<KEY>` to hooks), `skills` (adds to `skills/`), `commands` (replaces; object map with `source|content`), `agents` (replaces; `.md` files only), `hooks` (merges with `hooks/hooks.json`; file path or inline), `mcpServers`, `lspServers`, `outputStyles`, `workflows`, `experimental.{themes,monitors,evals}`. All paths must start with `./` and stay inside the plugin root. `claude plugin validate ./dir [--strict]`.

**Standard layout**: `.claude-plugin/plugin.json`, `skills/<name>/SKILL.md`, `commands/*.md` (legacy), `agents/*.md` (subfolders become name segments), `hooks/hooks.json` (wrapped in top‑level `"hooks"`), `.mcp.json`, `.lsp.json`, `output-styles/`, `workflows/*.js`, `themes/`, `monitors/monitors.json`, **`bin/`** (on Bash PATH while enabled; claude.ai/Cowork refuse plugins with top‑level `bin/` → put scripts in `scripts/`), `settings.json`.

**Rules / CLAUDE.md**: a plugin **cannot ship `.claude/rules/` or a CLAUDE.md** — "A `CLAUDE.md` at the plugin root isn't loaded as context, and `claude plugin validate` warns… To include instructions that load into Claude's context, put them in a skill." Always‑on rules must be either a skill, a hook, or injected via a `SessionStart` hook's `hookSpecificOutput.additionalContext` (≤10,000 chars; longer is spilled to a file with a 2,000‑char preview; reruns on resume) — exactly what lisa does. `.claude/rules/*.md` with `paths:` frontmatter exist only at project/user scope (an onboarding skill can *write* them into the project).

**Namespacing**: skill `skills/review/SKILL.md` in plugin `p` → `/p:review` (frontmatter `name` replaces last segment); agents → `p:reviewer` (`@agent-p:reviewer`); MCP server → `plugin:p:db`, tools `mcp__plugin_p_db__tool`.

**Skill frontmatter that matters**: `description`/`when_to_use` (1,536‑char cap, 1% context budget for the listing), `disable-model-invocation`, `user-invocable: false`, `allowed-tools` (pre‑approve e.g. `Bash(${CLAUDE_SKILL_DIR}/scripts/*.sh *)`), `disallowed-tools`, `model`, `effort`, **`context: fork` + `agent:`** (run in fresh subagent — the CoVe isolation primitive), `background`, **`hooks`** (skill‑scoped hooks, live for the rest of the session; `once: true`), `paths` (auto‑activate only for matching files), `arguments`/`$ARGUMENTS`, `` !`cmd` `` dynamic context injection, substitutions `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}` (survives updates — write state here, never in ROOT), `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_SESSION_ID}`. Keep SKILL.md < 500 lines; progressive disclosure via `references/`, `scripts/`.

**Hooks**: events `SessionStart|SessionEnd|Setup|UserPromptSubmit|UserPromptExpansion|Stop|StopFailure|PreToolUse|PermissionRequest|PostToolUse|PostToolUseFailure|PostToolBatch|SubagentStart|SubagentStop|TaskCreated|TaskCompleted|PreCompact|PostCompact|InstructionsLoaded|FileChanged|WorktreeCreate|…`; handler types `command|http|mcp_tool|prompt|agent`; exec form (`args`, no shell) vs shell form (quote `"${CLAUDE_PLUGIN_ROOT}"`); block with exit 2 or `{"decision":"block","reason":…}`; `Stop` receives `last_assistant_message` and can return `additionalContext` → **Stop hooks are the sanctioned verification‑loop primitive**; `onFailure: "block"` (v2.1.295+). Plugin hooks fire from session load regardless of which skill ran; narrow with `matcher`. Two plugins with the same name → one's hooks are dropped.

**Marketplace**: `.claude-plugin/marketplace.json` requires `name`, `owner{name}`, `plugins[]{name, source}`; optional `description`, `metadata.pluginRoot`, `renames` (append‑only migration map), `forceRemoveDeletedPlugins`, `allowCrossMarketplaceDependenciesOn`; entry fields `version`, `category`, `tags`, `strict` (default true), `displayName`, `relevance`, `dependencies`. Sources: relative `./plugins/x`, `{"source":"github","repo":"o/r","ref","sha"}`, `url`, `git-subdir`, `npm`, `archive`(+`sha256`), `command`. Keep entry name == manifest name. Validate with `claude plugin validate ./marketplace`.

**Private GitHub repo install**: users run `/plugin marketplace add owner/repo` (or `owner/repo#ref`); Claude Code runs the user's own `git` non‑interactively — probes `ssh -T git@github.com` and uses SSH, else HTTPS with a *stored* credential helper (`gh auth login && gh auth setup-git`); `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1` skips SSH; `marketplace.json` has no token field; `GITHUB_TOKEN` alone doesn't help background auto‑update unless a helper reads it. Team pinning: `claude plugin marketplace add owner/repo --scope project` commits to `.claude/settings.json`; admins use `extraKnownMarketplaces` + `enabledPlugins` (+`autoUpdate`). Updates propagate only when `version` changes (or omit `version` to track commits); release channels = two marketplaces pointing at different refs.

**Dev loop & QA**: `claude plugin init <name> [--with skills hooks agents mcp]` scaffolds under `~/.claude/skills/<name>/` (loads as `<name>@skills-dir`); `claude --plugin-dir ./p` for a session; `/reload-plugins`; `claude plugin validate`; `claude plugin tag` (release tags `<plugin>--v<version>` for dependency resolution); `claude plugin test`; Anthropic's `plugin-dev` plugin (`/plugin-dev:create-plugin`). **`claude plugin eval .`** (v2.1.269+): `evals/<case>/{prompt.md (frontmatter max_turns, allowed_tools), graders/*.md (type: llm|regex|tool_used|tool_order|file_exists|baseline, weight, arm), case.yaml (scaffold_script, add_dirs, history_file)}`, 3 runs/case, with‑ vs without‑plugin **Δ** baseline, `--threshold`, `--json`, `--trust-plugin`, `--max-cost-usd`, mock MCP servers under `evals/mocks/`; `claude plugin eval init` writes a suite interactively. **`/skill-doctor`** (v2.1.252+) reports per‑skill context cost + invocation counts, flags never‑used skills (Stats tab of `/plugin`). **`/doctor prompt-audit [path]`** (v2.1.283+) finds stale/contradictory instructions across CLAUDE.md, rules, skills, agents.

**Can an "onboard" skill write project files?** Yes — a skill is just instructions; give it `allowed-tools: Write Edit Bash(...)` (or `Read/Glob/Grep` plus the normal permission flow). Precedents: K‑Dense `scientific-writer-init`, `/harness-setup`, `lisa apply` (receipt file + ownership modes), `/init` with `CLAUDE_CODE_NEW_INIT=1` (multi‑phase: asks which artifacts to set up, explores with a subagent, follow‑up questions, reviewable proposal before writing). Natural targets: a `CLAUDE.md` section between markers, `.claude/rules/paper-*.md` (path‑scoped to `manuscript/**`), a `paper.toml`/`.paper-harness.json` config (venue, main tex, bib, engine, page budget, results dir), `.claude/settings.json` hooks/permissions, `.gitignore` entries, `quality_reports/` scaffolding. Persist cross‑project state in `${CLAUDE_PLUGIN_DATA}`.

## Thread 4 — Verification / anti‑hallucination patterns

**Chain‑of‑Verification (Dhuliawala et al., 2023)** — https://arxiv.org/abs/2309.11495 (full text https://ar5iv.labs.arxiv.org/html/2309.11495). Draft → plan verification questions → answer them → revise. Variants: *joint* (same prompt; copies the draft's errors), *2‑step*, **factored** (each question answered in its own prompt with *no draft in context*), *factor+revise* (explicit consistent/inconsistent cross‑check). Factored > 2‑step > joint: Wikidata list precision 0.17→0.36; MultiSpanQA F1 0.39→0.48; biography FactScore 55.9→71.4 (factor+revise). Implementation in Claude Code = `context: fork` subagent that receives extracted claims + sources, never the draft (your existing `claim-verifier` already does this).

**Citation existence verification**
- *How LLMs Cite and Why It Matters* (Naser, Feb 2026) — https://arxiv.org/abs/2603.03299: 10 LLMs, 69,557 citations checked against CrossRef/OpenAlex/Semantic Scholar; fabrication 11.4–56.8%; **multi‑model consensus (>3 models cite it) → 95.6% real; within‑prompt repetition (>2 of N replications) → 88.9%**; string‑feature classifier AUC 0.876 without any API call; newer models not reliably better.
- *CheckIfExist* (Feb 2026) — https://arxiv.org/html/2602.15871v1: strip LaTeX → parse BibTeX/free text → CrossRef top‑3 → fallback Semantic Scholar → cross‑validate with OpenAlex when score < 70/80; Levenshtein title similarity, family‑name containment for authors, year/journal; penalties −20 title/author mismatch, −10…−20 journal/fake author; labels Verified / Partial Match / Mismatch / No‑Issues; batch at 800 ms intervals; MIT, https://zabbonat.github.io/References-Validation/.
- **bibsleuth** (PyPI, used by claude‑scholar `check-refs`) — https://pypi.org/project/bibsleuth/: `bibsleuth check paper.tex`; existence without an LLM against OpenAlex, Semantic Scholar, CrossRef, arXiv, DBLP, PubMed; suggests missing DOIs; mis‑citation analysis optional with an LLM. Alternatives: citecheck, CiteSentry, bibverify, fixbib, BibGuard.
- Agents4Science built the same thing: title → web search → flag; **~44% of submissions had zero flagged refs, i.e. a majority had ≥1 suspicious reference** (https://arxiv.org/pdf/2511.15534).
- API limits: **Crossref** polite pool via `mailto=` (≈3 r/s queries, 10 r/s single‑DOI; read `x-rate-limit-*` headers; https://community.crossref.org/t/refining-rest-api-limits-for-improved-stability-and-reliability/16137 , https://crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/); **OpenAlex** (page updated 2026‑10‑15): 10 r/s keyless, 30 r/s free key, daily budget, free key = 10× keyless budget, cursor paging needs a key, `api_key=` or bearer (https://help.openalex.org/how-to-use-the-api/rate-limits-and-authentication); **Semantic Scholar**: 1,000 r/s shared keyless pool, 1 r/s per key initially; request key via form (https://www.semanticscholar.org/product/api). Design: Crossref first (DOI canonical), OpenAlex second, S2 for arXiv/CS; cache by normalized title; `mailto`/key via `userConfig`.

**AI reviewers / rubrics**
- **Sakana AI‑Scientist `perform_review.py`** — https://github.com/SakanaAI/AI-Scientist/blob/main/ai_scientist/perform_review.py: NeurIPS form (Summary, Strengths, Weaknesses, Originality/Quality/Clarity/Significance 1–4, Questions, Limitations, Ethical Concerns, Soundness/Presentation/Contribution 1–4, Overall 1–10 with anchors, Confidence 1–5, Decision Accept/Reject only); THOUGHT before JSON; `num_reflections=5`, `num_reviews_ensemble=5`, `num_fs_examples=1`, temperature 0.75; **negative vs positive system prompt** ("if unsure, reject" is default); Area‑Chair meta‑review averages numeric fields; ~70% balanced accuracy (Nature 2026 version). Known bias: scores higher than other reviewers.
- **Agents4Science 2025** (Bianchi, Queen, Thakkar, Sun, Zou) — https://arxiv.org/abs/2511.15534 ; FAQ https://agents4science.stanford.edu/faq.html: GPT‑5, Gemini 2.5 Pro, Claude Sonnet 4, same prompt, **1–6 scale, NeurIPS‑2025 guidelines as rubric; calibrated by iterating the instructions on anonymised ICLR 2022/2025 papers to maximise correlation with human scores**; avg ≥4.0 → human stage (79 of 253 complete submissions; 48 accepted; 62 desk‑rejected as incomplete). Pairwise Pearson 0.48; mean scores GPT‑5 2.30 / Claude 3.0 / Gemini 4.23; MAD vs humans 0.91 / 1.09 / 2.73; Gemini sycophancy ("groundbreaking… technically flawless"); AI reviewers caught abstract/body contradictions and numeric mismatches (R²=0.0148 vs 0.005); prompt‑injection scanner caught 2 papers.
- **ReviewerToo** (Oct 2025) — https://ar5iv.labs.arxiv.org/html/2510.08867: personas — stance (*critical*, *permissive*, *default*), epistemic (*theorist*, *empiricist*, *pedagogical*, *pragmatist*), stylized (*visionary*, *probabilistic*, *impact‑driven*), plus *reproducibility*, *fairness*, *big_picture*; every judgment must cite a manuscript span or retrieved literature; ICLR‑2k binary accuracy: theorist 71.9, default 70.6, pedagogical 70.3, empiricist 67.6, **critical 53.6, permissive 46.8**; metareviewer over all personas 81.8% (humans 83.9%). Lesson: *dispositions = epistemic lenses, not stance*; ensemble + meta‑review; guard against post‑rebuttal sycophancy.
- **EloReview** (Jan 2026) — https://arxiv.org/abs/2601.08829: personas Expert/Critic/Bluffer/Optimist/Harmonizer/Skimmer + Area Chair; Elo weighting improves AC accuracy but reviewers game it.
- **Stop Automating Peer Review Without Rigorous Evaluation** (ICML 2026 oral) — https://arxiv.org/abs/2605.03202: AI reviews show a **hivemind effect** (excess agreement) and are **gameable by "paper laundering"** (LLM rewrite raises AI scores without new results); required properties: non‑gameability + review diversity. Related: LLM‑REVal (LLM‑written papers 78% AI‑acceptance vs 49% human), LLM‑as‑reviewer prompt‑injection study (https://arxiv.org/abs/2509.09912: rating inflation for weak papers; field‑specific hidden instructions do manipulate reviews).
- **ReviewEval** — https://arxiv.org/abs/2502.11736: evaluate reviews on alignment with humans, factual accuracy, analytical depth, constructiveness, guideline adherence.
- **ICLR 2025 Review Feedback Agent** — https://blog.iclr.cc/?p=994 (paper https://arxiv.org/abs/2504.09737): multi‑LLM actor/aggregator/critic pipeline with reliability tests before posting; 26.6% of reviewers revised; 89% judged improved. Pattern to copy: *critique the critique* (meta‑reviewer checks every quote appears verbatim in the paper before a finding is surfaced).
- Practical anti‑sycophancy rubrics already in the wild: ARS reviewer (seats blind to each other; DA CRITICALs must be adjudicated; "no manufactured balance and no finding quotas"; PARTLY_MEETS/DOES_NOT_MEET/NOT_ASSESSED), SNL red‑team (findings list only; reviewer never sees self‑assessment; grep evidence pasted), flonat `promise-checker.sh` (Stop hook catches "I saved X" lies).

## Thread 5 — LaTeX tooling for agents

- **latexmk** (CTAN README https://tug.ctan.org/support/latexmk/README): "which of bibtex or biber to use is determined automatically" (it keys off the `.bcf` that biblatex writes vs `\bibdata` in `.aux`; override with `-bibtex`, `-bibtex-`, `-bibtex-cond` / `$bibtex_use`); dependencies from `.fls/.log/.aux`; `-pdf` (pdflatex), `-pdfxe`/`-xelatex`, `-pdflua`/`-lualatex`; `-interaction=nonstopmode -halt-on-error` (set in `$pdflatex`), `-f` (force past errors), `-g` (force rerun), `-c`/`-C` clean, `-outdir=build`, `-pvc` watch, `-silent`. Agent‑friendly invocation: `latexmk -pdf -interaction=nonstopmode -halt-on-error -file-line-error -outdir=build main.tex` and check exit code; keep the project `make` as the authoritative build when one exists (your manuscript uses `pdflatex→bibtex→pdflatex×2` via Makefile).
- **Log parsing**: `texfot` (TeX Live; filters live output to errors, over/underfull boxes, undefined citations; https://manpages.ubuntu.com/manpages/jammy/man1/texfot.1.html); **`texlogsieve`** (reads the `.log`, per‑package silencing, summary report with `--box-detail`; https://www.mankier.com/1/texlogsieve); minimal regexes used by skills: lines starting `!` = errors; `Overfull \\hbox (\d+(\.\d+)?pt too wide)` / `Underfull`; `LaTeX Warning: Citation .* undefined`; `LaTeX Warning: Reference .* undefined`; `There were undefined references`; `Label(s) may have changed. Rerun`; `Package .* Warning`. Overfull boxes: report with a pt threshold (e.g. flag > 10 pt) for human judgment; never auto‑fix.
- **Linters**: **chktex** (`chktex -q -n1 -n8 -n36 -I0 main.tex`; `-n` mute warning no., `-w/-e/-m` reclassify, `-l` local rc, `-v0` terse machine format, `-I` follow `\input`; inline `% chktex NN`; https://manpages.debian.org/testing/chktex/chktex.1.en.html , CTAN https://ctan.org/pkg/chktex); **lacheck** (heuristic: unmatched braces/envs/math delimiters, missing `~` before `\cite`/`\ref`, italic corrections, double spaces; UNIX‑style `"file", line N:` output; no suppression options; "crude approximation" — treat as advisory; https://manpages.debian.org/testing/lacheck/lacheck.1.en.html).
- **Word/page budget**: **texcount** (`texcount -inc -sum -brief main.tex` for one total following `\input`; `-merge`, `-sub=section` per‑section table, `-v -html` colour report; `%TC:ignore … %TC:endignore`, `%TC:macro` rules; headers/captions/math counted separately — https://app.uio.no/ifi/texcount/howto.html , CTAN docs https://ctan.org/pkg/texcount); page count via `pdfinfo build/main.pdf | grep Pages` and compare with venue limit (pattern used by compile skills); **wheretotrim** (CTAN https://ctan.org/pkg/wheretotrim) reports the page/column where the least text must be cut to drop a page; per‑section page map from `\label` positions in `.aux` or `pdftotext -layout` + heading grep.
- **Document class → venue profile detection**: no off‑the‑shelf tool found; implement a grep over the main file (resolving `\input`/`\include`) for `\documentclass[opts]{cls}` plus `\usepackage{…}`: `llncs`→Springer LNCS/CCIS (your case; `\bibliographystyle{splncs04}`); `svjour3`/`sn-jnl`→Springer journals (Machine Learning journal uses `sn-jnl` with `sn-mathphys-num`/`sn-basic` options); `IEEEtran` with `conference`/`journal`/`compsoc`/`comsoc` options (CTAN https://ctan.org/pkg/ieeetran); `acmart[sigconf|sigplan|acmsmall|acmtog]`; `elsarticle[preprint|review|final,3p|5p|1p]`; `revtex4-2[aps|aip,prl|pra…,reprint|preprint]`; `amsart`/`siamart`; `article` + `neurips_2026.sty` / `icml2026.sty` / `iclr2026_conference.sty` / `acl.sty` / `aaai2x.sty` / `jmlr2e.sty`; `plos2015`; `nature`/`sn-nature`. Also detect engine (`fontspec`→xe/lua), bib backend (`biblatex`+`\addbibresource`→biber; `\bibliographystyle`→bibtex), anonymity (`\anonymous`, `review` option, `\author` commented), two‑column, and page limit per profile. This is my synthesis from the CTAN class docs; keep profiles in a `venues/*.yaml` table editable by the user.
- **arXiv pre‑flight** (official https://info.arxiv.org/help/submit_tex.html ; Overleaf checklist https://docs.overleaf.com/troubleshooting-and-support/checklist-for-arxiv-submissions): TeX Live 2025 default (2023 selectable); biblatex `.bbl` must be **format 3.3** for TL2025 (3.2 accepted only on TL2023) and from the right backend; upload `.bbl` named like the main file or include `.bib`; no `.aux/.log/.out/.pdf` of sources; hidden files deleted; compile runs from submission root; no `\pdfoutput`, no `[pdftex]` driver options, `hyperref` without options (use `\hypersetup`, or `00README.XXX` with `nohypertex`); pdfLaTeX figures as `.pdf/.png/.jpg` (no `.eps`), no `-eps-converted-to.pdf`; `\today` warnings; no JavaScript in PDF; `cleveref` breaks under TL2025; `minted` changed. Tools: **arxiv‑latex‑cleaner** (strip comments/`\iffalse`, unused files, resize images, `--keep_bib`, `--commands_to_delete`, `cleaner_config.yaml`; https://github.com/google-research/arxiv-latex-cleaner), **latex2arxiv** (`--dry-run --json` pre‑flight with `[error]` on shell‑escape packages/`psfig`, warnings for `\today`, `.eps`, missing `.ind`, `.bbl` version mismatch, undefined citations; non‑zero exit for CI; https://pypi.org/project/latex2arxiv/), ALC‑NG (https://github.com/COMSYS/ALC-NG/), claude‑scholar `arxiv-prep`, armory `arxiv-preflight` skill.

## Design ideas worth adopting (each tied to a source)

**Packaging / onboarding**
1. Ship as a **marketplace repo** (`.claude-plugin/marketplace.json` + `plugins/<name>/`) installable with `/plugin marketplace add owner/private-repo`; keep entry name == manifest name; omit `version` while iterating, bump it for releases; validate in CI with `claude plugin validate --strict` and gate with `claude plugin eval --threshold` (Anthropic docs; ARS ships `evals/`).
2. Provide an explicit **`/<plugin>:onboard`** skill (K‑Dense `scientific-writer-init`, `/harness-setup`, `lisa apply`/`agent-ready`, `/init` new flow): inventory sources read‑only (main `.tex`, class, bib backend, Makefile, results dir, review reports), *propose before writing*, then write a `paper.yaml` (venue profile, engine, page budget, claim→artifact map), marker‑delimited `CLAUDE.md` section, path‑scoped `.claude/rules/paper-*.md`, and a `gaps.md` of questions only the author can answer; re‑runs are absorption runs (lisa).
3. Adopt lisa's **three ownership modes** for files you write into a project (enforced / created‑once / merged) plus an `apply-receipt.json`, and never delete hook targets mid‑session (lisa #4335).
4. Because plugins can't ship rules/CLAUDE.md, inject always‑on paper rules via a **`SessionStart`/`SubagentStart` hook that concatenates `rules/eager/*.md` into `additionalContext`** (≤10 KB; reference docs loaded on demand) — lisa `inject-rules.sh`.
5. Keep **commands thin, skills thick** ("Use the /x skill to …"); skills carry `references/` and `scripts/`; put deterministic checks in `scripts/` and pre‑approve them with `allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/*)` (lisa, lingzhi227, Anthropic skills docs). Follow claude‑scholar's "don't overbuild" rule: a skill earns its place only via external API, programmatic verification, or a forget‑prone checklist.
6. Use `${CLAUDE_PLUGIN_DATA}` for caches (Crossref/OpenAlex lookups, venue profiles), `userConfig` for `mailto`/API keys (sensitive→keychain).

**Ideation & grilling**
7. **Brainstorm interview → binding contract file** (SNL `project_context.md`: identity sentence, venue constraints, claims with evidence pointers, evaluation plan, positioning, section architecture, locked decisions vs open questions, figures needed; your `/interview-me` spec is the analogue). Enforce "update the file, don't just tell Claude".
8. **Grilling** = one question at a time with a recommended answer, agent looks facts up itself, only genuine decisions go to the human, no action until shared understanding (mattpocock `grill-me`; superpowers brainstorming). Add ReviewerToo‑style *lenses* (theorist, empiricist, pragmatist, reproducibility) rather than harsh/lenient stances, which the data shows are miscalibrated.

**Writing & self‑verification**
9. **Mechanical + semantic gates with IDs** (SNL M1–M18/S1–S31): every finding cites a rule ID, line, fix; "pasted grep output is the audit record; never report clean on a mental pass".
10. **Independent red team in a forked context** that sees only the draft + checklists, never the author's self‑assessment, and returns findings not verdicts; loop until clean with a **bounded cap** and escalation (SNL red‑team protocol + lisa block counter + harness 8‑cycle cap).
11. **Deterministic completion gate via Stop hook**: block stop until a structured verdict file (claims ↔ evidence with sha256, `established|not-established`) is fresh and all required claims pass; bounded by a per‑session counter so stuck loops escalate (lisa `enforce-verification-gate.sh`; Claude Code `Stop` hook docs). For a paper: "compile clean + bib verified + claims audited" verdict JSON under `quality_reports/`.
12. **Codify** every manual verification into a repeatable check (lisa step 7): e.g. after a reproducibility audit, write a script that re‑derives Table 1 numbers from `src/results/*.json` and diff them in CI.
13. **Promise checker** Stop hook: detect "I saved/updated/verified X" claims in `last_assistant_message` with no matching tool call (flonat `promise-checker.sh`).

**Citations & claims**
14. Three‑source citation existence check (Crossref → OpenAlex → Semantic Scholar) with normalized‑title Levenshtein + author family‑name containment + year, labels Verified/Partial/Mismatch/Missing (CheckIfExist); wrap `bibsleuth` instead of rewriting (claude‑scholar). Add Naser's cheap pre‑filters: *multi‑model consensus* and *repetition* for LLM‑suggested references; treat `.bib` entries as untrusted until verified.
15. **Factored CoVe** for all factual/numeric claims: extract claims → verify each in an isolated subagent with only sources in context → revise (Dhuliawala et al.; your `claim-verifier` agent).
16. Cross‑artifact checks: contradictions between abstract/body/tables and numeric mismatches were exactly what AI reviewers caught at Agents4Science — make "internal consistency" a deterministic pass (numbers in text vs tables vs `results/*.json`), not a prose review.

**Simulated peer review**
17. Use the **NeurIPS form as the rubric** (Sakana `perform_review.py` fields; Agents4Science 1–6 scale) with reflection rounds + ensemble + Area‑Chair meta‑review; default a *skeptical* system prompt ("if unsure, reject").
18. **Reviewer seats blind to each other; Devil's Advocate CRITICALs must be adjudicated visibly; no finding quotas; NOT_CALIBRATED label until a calibration run** (ARS reviewer). Calibrate on papers with known decisions when possible (Agents4Science used ICLR 2022/2025).
19. **Every finding must quote a manuscript span**, and a critic step verifies quotes exist verbatim before surfacing (ReviewerToo grounding; ICLR 2025 feedback agent).
20. Treat the manuscript as **untrusted input** to reviewers; scan for prompt injection (Agents4Science caught 2; LLM‑as‑reviewer study shows field‑specific injections work). Add a **"laundering" check**: if a stylistic rewrite moves the simulated score by > 1 point with no content change, flag the reviewer, not the paper (Baumann et al., ICML 2026).

**Formatting / compilation**
21. One **`compile` skill** that honours the project's own build (Makefile) else `latexmk -pdf -interaction=nonstopmode -halt-on-error -file-line-error`, auto‑detects bibtex vs biber, then parses the log into errors / undefined refs+cites / overfull (pt‑thresholded) / reruns, and reports `pdfinfo` page count against the venue budget (weinaike, lingzhi227, ARIS skill; latexmk README). "Fix the first error, not the last."
22. **Venue profile detection** from `\documentclass` + key `\usepackage` lines mapped to a `venues/*.yaml` table (page limit, anonymity, bib style, engine); your LLNCS/Springer‑ML case first (own synthesis from CTAN class docs).
23. **Pre‑submission fan‑out** (claude‑scholar `presubmit-checks`): run chktex/lacheck/texcount/compile/citation/figure/placeholder‑grep checks in parallel subagents and merge by severity; include the arXiv rule set (TL2025, bbl 3.3, hyperref options, `.eps`, hidden files, `\today`) and wrap `arxiv-latex-cleaner`/`latex2arxiv --dry-run --json`.
24. **Report‑only critics, non‑destructive transforms**: proofread/critique skills never edit; packaging skills write to a copy (claude‑scholar).

**Operations**
25. Files‑first state that survives compaction: plan files, session logs, `current-focus.md`, a `[LEARN]` ledger that a gardener promotes into rules only with human approval, and a human‑only rules file that is expected to shrink as prose becomes hooks (flonat; lisa `PROJECT_RULES.md` + learnings ladder; your existing MEMORY.md two‑tier scheme).
26. Add `evals/` with `tool_used: Skill` + `llm` rubric graders for each skill and a `/skill-doctor` pass to prune skills that never fire (Anthropic plugin‑evals docs).
